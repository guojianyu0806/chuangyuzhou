开发题覆盖不同结果类型，不能只用“创建成功”的任务。留出题应包含新的初始状态、措辞、组合、日期与边界情况；仅换名字或数字的同模板变体不足以证明独立泛化。

**16题的实际内容和答案当前均为空。** 应由没有调试本轮提示词的人独立编写并复核。开发者只获知类别、协议和支持范围，冻结前不能查看留出请求、状态、答案或错误反馈。独立人员在自己的授权资料区保管，冻结时记录任务文件hash、负责人和时间。若团队无法安排独立人员，就如实标为“开发者留出划分、独立性不足”，不能改称独立金标。

正式留出评测只在代码、提示词、模型配置和评分准则冻结后进行。看到留出错误后可以修复产品，但该轮结果仍保留，修复后的版本须使用新的独立留出题或明确说明已发生暴露。

## 3. 每题如何规定成功

每题都要包含：编号、类别、初始状态、当前空间/选中模块、原始请求、附件或资料、允许变化、禁止变化、必要结果、有效澄清及可接受替代结果。多轮任务预先写清何时给出用户补充，不根据某一模型的表现临时放宽。

以确认后的真实状态和视图绑定为依据，不以助手说“完成”或HTTP返回200作为成功。至少核对：

1. 对象和字段：目标记录正确；日期、选项、关联ID和值满足要求；未要求改变的内容保留。
2. 布局：12列范围、最小尺寸、无重叠、页面归属正确；多个合法坐标均可通过。空间关系、宽度和阅读顺序比固定像素更重要。涉及坐标的开发题使用0起始网格索引，三个条件都应得到这份说明。
3. 共享数据：列表、看板、日历引用同一集合；改一次记录后各视图一致，不能靠复制记录实现。
4. 稳定引用：字段或选项改名保留其ID；现有绑定不失效；新ID可不同，但应能建立一一对应关系。
5. 来源：asset/hash/quote存在与语义支持分别判断。只验证引文位置存在，不代表原文支持所填写日期或事实。
6. 澄清：必要信息不足时零写入，并问到缺失点；清晰任务不断追问属于额外负担，不算自动成功。
7. 恢复：确认前有修改时拒绝旧方案；撤销条件不满足时保留所有现状并说明原因，不留下部分回滚。

比较状态时排除正常产生的系统元数据，如revision、回执编号、时间戳和usage；已有对象的业务ID不能随意忽略。新对象按任务中的名称、类型和关系选择，再检查数量与约束。

JSON中的`expected.all`列出声明式判断，`preserve`中的`except`列出允许变化的路径；`<new-field-id>`、`<new-record>`等表示由实际结果定位的新对象。它不是已经实现的通用断言语言。接入执行器前，必须把每种check映射成明确的自动检查或人工检查，不能遇到未实现check就默认通过。

开发题023和024带`engineering_recovery`标记，需要研究员在指定阶段插入人工变化。它们单独报告工程恢复结果，**不放进三条件常规任务效率的相同分母**。正式40题的同类技术干预项也须在开测前标记，不能看到失败后再排除。

## 4. 三种条件如何公平比较

| 条件 | 操作方式 | 统一条件 |
| --- | --- | --- |
| A 人工 | 使用同一创宇宙界面，手动完成 | 同一版本、相同初始数据和资料、相同目标、相同设备及练习机会 |
| B 聊天建议 | 同型号模型提供文字建议，参与者手动操作界面 | 获得与C相同的相关状态、资料、偏好和操作能力说明；可追问但不得自动写入 |
| C 完整AI | 伙伴生成方案，参与者核对确认并纠错 | 同型号、相同推理模式/预算与输入范围；计时包含预览、确认、失败与修正 |

B不能故意缺少关键ID对应说明、附件或当前状态；C也不能提前获得标准答案或其他条件中已经整理出的结果。B和C的系统提示可以适配各自输出形式，但信息可见范围、模型版本和生成参数必须记录，并说明差异。手动条件可以使用界面中正常提供的模板与搜索，不能人为隐藏功能。

所有条件从独立、等价的初始状态开始。每次恢复均使用合成评测实例，不清空用户个人实例。允许的帮助、最多追问轮次、超时上限和人工纠错方式在试测后冻结。建议先做一轮不计成绩的流程试测，确定例如每任务8分钟的上限；正式实施采用什么上限需填在记录中，不能把建议当作已采用值。

## 5. 至少6人的交叉顺序

建议至少6名目标用户，每人经历A、B、C；为平衡熟悉和疲劳影响采用下表顺序。若招募12人，再重复一组顺序并换任务分配。人数不足6时如实披露，不填不存在的参与者。

| 计划编号（非真实参与记录） | 第一阶段 | 第二阶段 | 第三阶段 | 实际匿名编号/是否完成 |
| --- | --- | --- | --- | --- |
| P01 | A | B | C | 待填写 |
| P02 | A | C | B | 待填写 |
| P03 | B | A | C | 待填写 |
| P04 | B | C | A | 待填写 |
| P05 | C | A | B | 待填写 |
| P06 | C | B | A | 待填写 |

每阶段可先安排2个匹配难度的普通任务，每人共6个计时任务；恢复干预项另外安排。三个阶段使用X/Y/Z等价任务变体，同一人不重复做完全相同题目，防止记忆答案。任务变体与条件轮换独立编排，不能让C始终拿最简单一组。编排和难度复核完成前不要实际开测。

给所有参与者相同的短教程和不计分练习，确保会切换使用/布置、找到资料、确认及撤销。教程不展示计分题的答案。不同参与者之间不共享解法。任务完成后由核对者检查最终状态，参与者自称完成不能替代评分。

建议以参与者内差值和各条件中位数报告用时，附成功数/总数及失败案例。6人属于探索性试用；一次参与者的多个任务不是多个独立用户，不据此宣称大样本显著性、所有人适用或长期效率提升。

## 6. 指标、分母与失败处理

| 指标 | 明确口径 |
| --- | --- |
| 最终任务成功率 | 在规定时间内满足全部必要结果且无禁止变化的任务数/预先分配的同类任务数。报告普通任务、澄清题和工程恢复题各自分母 |
| 首次方案正确率 | 首次待审核方案已经满足要求且不会误改的任务数/要求生成方案的题目数；被校验器拦截计失败，不因未写入变成成功 |
| 错误/额外写入 | 确认后不在允许变化范围内的对象—字段变化数及发生此类变化的任务数；错误对象、漏改、重复对象分别列出 |
| 被拦截的错误方案 | 被领域校验、版本检查等拦下的方案数，单列原因；不要混同已经发生的误写 |
| 布局约束满足 | 全部布局约束满足的任务数/含布局要求的任务数；同时记录边界、重叠、阅读顺序各失败数 |
| 澄清有效性 | 应澄清题中问到必要缺失点且没有写入的题数/应澄清题数；清晰题的额外澄清率另报，防止靠全部拒绝获得虚假安全表现 |
| 来源与语义 | 引文存在/版本匹配按程序检查；事实是否被原文支持由独立人员判定，逐字段报告，不合并为一个“引用正确”值 |
| 撤销/版本保护 | 成功恢复且保留后续无关编辑，或正确拒绝有依赖的撤销；分别报告可撤销与应拒绝的题数，不把任何拒绝都记成功 |
| 完成时间 | 从展示请求并开始操作到参与者提交结果，含读取资料、模型等待、审核、确认、澄清、人工纠错。记录失败/超时，不把它们记为0或从总样本删除 |
| 人工负担 | 手动点击/编辑次数、澄清轮数、字段纠错次数、撤销次数、研究员帮助次数；记录计数方法，不凭屏幕观感估算 |
| 模型时间与调用 | 每请求耗时、每任务调用次数、每次模型/参数/提示词版本/日期与usage。小样本优先逐题和中位数，尾部分位数不作稳定性承诺 |
| 费用 | 按官方价格快照和实际输入、缓存、输出用量计算；缺价格或usage时null，不能填0。失败与重试费用同样计入，另列未知费用条数 |

普通失败、超时和主动放弃保留在预先分配任务的记录中；因账号余额等外部原因未尝试的任务标为“未尝试”，同时给出计划数和实际尝试数。不能只报告完成的题目。超过时间上限仍成功的，可另报继续完成时间，不追记为限时成功。

预算应在少量真实开发调用后估算。任务数×条件数×重复数不等于实际调用数，追问与重试可能增加调用。默认不自动重试；是否允许重试和上限在开测前规定。若只知道部分费用，报告“已知费用合计＋未知调用数”，不要将已知部分写成完整总费用。

## 7. 材料授权与独立复核

优先使用合成资料。真实资料必须取得可用于本次测试的授权或充分脱敏；链接保存不等于网页内容已获授权或已被系统读取。不要使用个人宇宙或旧校园版的数据库、附件、账号或模型配置充当新平台数据。

参与者在开始前知晓：操作会被计时，匿名结果用于产品验证；只有明确同意才录屏；真实AI条件会将选定合成/获授权内容发送给模型服务；可以中止。记录研究者编号和匿名参与者编号，姓名与联系方式不进入测试数据或提交材料。密钥、账号、Cookie和初始化口令不得出现在录屏、结果或源码包中。

独立核对者不能参与本轮提示词调优。先检查任务是否可完成、是否唯一或允许哪些等价答案、日期与时区、允许/禁止变化及证据语义，再签署复核状态。初始状态校验通过只证明数据结构合法，不证明题意和答案正确。

建议两人独立复核有歧义的题目，保留各自判断并由第三人或预定规则仲裁；人手不足时至少记录单人复核这一限制。审查模型结果时尽量隐去条件名称，先看请求、原文和最终状态。复核者未知或尚未检查的字段填写“待复核”，不能默认正确。
