# 聊天建议对照输入包

这是正式试用前的准备工具，只生成公开合成开发任务的B条件输入。没有真实模型调用、参与者、计时结果或成功率。原24题v1、原6题及历史结果保持原样，16题独立留出不包含在内。

```powershell
# 默认预览22条普通/澄清题，不读配置、不联网、不写文件。
node evaluation/build-chat-advice-inputs.mjs

# 固定时钟和公开型号，生成可复现输入包。
node evaluation/build-chat-advice-inputs.mjs --write --at 2026-10-01T00:10:00.000Z --model deepseek-flash

# 工程恢复题只可单独研究，不能混入普通真人效率分母。
node evaluation/build-chat-advice-inputs.mjs --cases cu-platform-dev-023,cu-platform-dev-024 --at 2026-10-01T00:10:00.000Z

node --test evaluation/chat-advice-inputs.test.mjs
```

每次 `--write` 新建本项目 `.cu-runtime/evaluation/chat-inputs-时间-随机标识/`，保存 `chat-advice-inputs.json` 与SHA256，不覆盖旧包，不复制运行数据库或配置。Node.js 25.7.0已验证程序接口与离线传输协议；正式打包验收以最新整合集为准。

程序接口：`buildChatAdviceInputs({cases,config:{provider,model},now})` 返回输入包。`config`仅接受公开型号与provider，不接收Key或完整私有配置。`adviceProviderInput(packet,taskId)` 在验证哈希后返回 `{system,user}`；它本身没有网络或执行能力。受控实测若后续调用模型，凭据应由专用实例在另一个授权步骤提供，不能写入输入包。

输入直接使用与完整AI相同的 `buildPlannerContext`：当前对象ID、选中模块、偏好、记录、资料、模板附件和时钟均保留；另一空间、标准答案和研究员干预步骤不进入消息。动作目录仅说明能力，B模型返回最多5项人可阅读建议或澄清，不能自动提交动作。参数快照使用相同provider协议：指定型号、关闭thinking、JSON响应、最大10000输出token、90秒超时，不发送temperature；保存模型、提示词版本、代码与上下文哈希。

相同信息不保证相同token用量；B与C输出协议和执行方式不同，实际usage及等待必须记录。此工具生成的冻结时钟不等于C真实请求已经采用同一时钟：试测时必须核对C的context/clock/prompt/代码版本，不能拿不同日期、不同资料或不同条件的请求直接比较。022旧题要求询问基准日的部分已与可信时钟功能不完全一致，仍需独立人员审查；不强迫模型重复询问已知信息。

三种条件的初始实例恢复、教程、顺序与任务变体轮换、人工操作计时、许可及语义核对仍由[试用协议](平台评测设计与试用记录模板_v1.md)约束。本生成器不完成上述研究工作，也不把建议文本算作已完成任务。正式结果必须包含失败、超时、未尝试及人工纠错；未知费用保持null。
