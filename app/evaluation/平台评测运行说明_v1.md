# 24条平台开发题运行说明

本运行器独立于原来的6条 smoke：原 `run-development.mjs`、原评测结果、`platform-development-v1.json` 和评测设计 v1 均保留原样。新入口为 `evaluation/run-platform.mjs`。题目是 AI 代理按规则构造的合成开发数据，预期字段由作者显式设置，尚需未参与提示词调优的人独立复核；不是调用待测模型生成答案。

## 使用方式

在创宇宙项目目录运行，已用 Node.js 25.7.0 验证。

```powershell
# 默认只列出24条开发题，不读取配置、不调用模型、不写结果。
node evaluation/run-platform.mjs

# 离线预设回复经过真实规划协议、领域预演、提交与机械评分。
# 仅用于工程回放，不是AI效果测评。
node evaluation/run-platform.mjs --fixture

# 可选只运行指定开发题；不支持holdout。
node evaluation/run-platform.mjs --fixture --cases cu-platform-dev-019,cu-platform-dev-023

# 只有显式live才读取配置并产生真实API费用；路径必须是本项目
# .cu-runtime中的普通非链接配置文件。请替换占位路径。
node evaluation/run-platform.mjs --live --config-file .cu-runtime/你的专用配置.json

node --test evaluation/platform-evaluation.test.mjs
```

配置内容格式是 `{ "provider": "deepseek", "model": "deepseek-flash", "apiKey": "用户专用Key" }`，由现有 `config.mjs` 验证。支持的模型以当前 provider 为准。不要把真实 Key 写入源码、题库或报告。`--fixture` 与 `--live` 互斥，`--config-file` 只有在 `--live` 时有效；路径越界、目录联接/软链接、硬链接、非普通文件都会拒绝。运行器不读取数据库、不继承个人或旧竞赛实例的凭据，不修改产品运行状态。所有业务提交仅发生在合成状态的内存副本中。

程序接口：

```js
import {runPlatformEvaluation} from './evaluation/run-platform.mjs';
const result = await runPlatformEvaluation({fixture:true,writeResults:false});
// {summary, records}：没有文件输出、没有真实模型调用。
// 授权实测时可由调用方显式传 {live:true,config}，不要记录config。
```

注入 `fixtureProvider` 只允许 `fixture:true`，会始终标记离线回放。没有预设回复的题会记录缺失，错误回复会记录错误，不跳过校验后强行记通过。真实调用发生401/402/429、网络或超时错误后会中止批次；未尝试题号保留在 summary 中。

## 输出与指标

运行模式的默认输出为本项目 `.cu-runtime/evaluation/platform-时间-随机标识/`，每次新建唯一目录，不覆盖旧结果。内含逐题 `results.jsonl`、汇总 `summary.json` 和可阅读的 `metrics.csv`。没有 Key 或原始远程错误响应。JSONL 记录合成输入、初始/最终状态、通过协议验证的方案、逐项约束状态、模型/提示词版本、时间、usage 与源码哈希；协议解析失败时只保留脱敏错误码和可得的 measurement，不保存未验证的原始响应。

- 20道普通操作、2道澄清、2道恢复保护分开汇总。023实测旧方案在中途人工编辑后被领域层拒绝；024实测后加视图依赖新集合后，撤销旧回执被拒绝并保持状态。这两题不进入普通任务效率分母，也不代表一般撤销成功率。
- 机械检查包括数量变化、对象字段、稳定ID、字段和选项结构、共享集合绑定、布局、模板结构与ID重映射、来源hash/精确引文、保护范围内的额外改动。无法识别的约束标记 pending，不能计作机械通过。
- `extraWriteCount` 是 `expected.preserve` 保护范围内发生变化的字段路径或新增/删除对象数；同一对象可贡献多个路径。它不是已完成的全部语义误改率。没有声明保护的表不会凭空推导限制。
- 引文存在仅证明可追溯，不证明语义支持。来源语义、澄清问题质量、额外列出的人工判断均 pending。即使全部机械检查通过，24题的独立金标复核仍 pending，`overallSuccess` / 最终成功率保持 null，不宣布已完成真实用户任务。
- 耗时只代表脚本的模型规划/内存提交与检查耗时，不含用户确认和操作时间；人工耗时为 null。usage 仅累计 API 实际返回的数值；没有价格依据时费用保持 null。fixture 的耗时与通过数不能解释为真实AI性能。
- 错误、超时、拒绝分别计数；失败率分母是已尝试题，未尝试列表另报。约束未实现的题单独待判，不以‘无法评分’冒充已证失败。总体正确率和效率结论仍需独立复核与真人对照。

## 冻结题目与当前局限

v1 数据的 SHA256 是 `a46ba42e22ac999820275ae0661e2a3ca260c0f93d6eb1a464c370b6a8e9e0e4`；运行器会校验此值。数据中的 `constraintStatus: declarative_not_yet_integrated_into_runner` 是生成当时的状态，保留以保证历史可追溯。本新增运行器已经接入上述机械约束，实际覆盖及 pending 以每次结果里的逐项 checks 为准。

022的旧标准提到澄清基准日期。规划器1.0.1已加入服务器可信时钟，因此不应强迫模型重复询问已知基准日；“下周”仍未指定星期，需人工判断追问是否足够。该旧期待仅留作人工复核项，运行器不以关键词判定澄清是否正确，也不改写v1来取得通过结果。

16道留出题仍未编写，未执行，没有标签。它们应由未调优人员独立编写和复核，不应由开发调优人员补成‘独立金标’。现有24题已经是开发上下文，不能后改标签为留出。真人、聊天建议、完整AI的公平对照与至少6名参与者交叉顺序，沿用《平台评测设计与试用记录模板_v1.md》，本CLI不伪造人评或聊天人工录入结果。

本次新增的是运行器、评分器、离线预设回复、测试和此说明；没有覆盖旧版本成品，也没有执行真实模型或真人试用。
