# 创宇宙：同一项目的早期开发与 Git 补录说明 v3

更新日期：2026-10-20。本文为现在整理的来源说明，原始消息、初始代码补丁、旧发布包清单及补录提交索引分别保存，不冒充当时形成的文档或提交。

## 结论与记录边界

“宇宙”是同一项目的早期名称，后更名为“创宇宙”并持续迭代。早期以个人日常使用为目标，后持续实现可组合工作台；目录复制表示开发与运行环境隔离。已找到从最初需求到首批代码的原始对话，以及 28 个个人版源码发布包；其中 25 个截至比赛复制使用的 0.15.0，另外 3 个属于分叉后个人版继续开发的 0.16/0.17。

检查原工作台目录及 frontend、backend、deployment、mobile 子目录，未发现 `.git`。在“宇宙”与此前“创宇宙”两份相关开发对话的实际工具调用中，也没有找回 `git init`、`git commit`、`git push` 等成功提交记录。“宇宙”对话在 2026-09-20 的两次 `git status --short` 后明确返回 `fatal: not a git repository`。这支持“本次没有找回早期 Git 历史”的结论，不能排除尚未定位的其他备份存在历史。

此前建立独立分支 `codex/yuzhou-historical-snapshots`，把 25 个留存发布包按先后逐版补录。**这些是现在创建的真实 Git 提交，作者时间和提交时间均为本次实际补录时间；不是恢复出来的早期原始提交。** 每条提交附有原包名称、SHA-256、源文件数量、与前一包的增删改清单及补录说明。`source/` 保持发布包里的文件字节，不运行旧部署脚本。

比赛主线原有 188 条提交及其 SHA 保留，补录分支没有被伪接成它的父历史。本说明及证据另以现在的文档提交保存。补录可以展示留存版本之间的修改，不能据此声称当时已逐步使用 Git，也不能保证组委会接受其替代原始过程记录。

## “宇宙”与比赛导入基线的衔接

旧包 `0-15-0-20261008-123114.tar.gz` 的 SHA-256 为：

```text
1652fb66560a86ad5a91129ec350df02f13d3f955b4fd8d52054207f22a797f0
```

该包包含的 94 个文件，全部与比赛已有的 [0.15.0 导入清单](../evidence/provenance/yuzhou-0.15.0-import.json) 逐字节哈希一致。清单总计 150 个文件，覆盖的范围比部署包更大；不能把 94 个文件的验证扩写为全部 150 个都由旧包独立证明。

对照真实导入提交 `ac73158`：94 个旧包文件中 63 个字节完全一致，31 个只有换行编码差异，规范化 CRCRLF/CRLF 为 LF 后内容全部一致。对导入清单的全部 150 项，118 项与 Git 文件字节完全一致；其余 32 项中的 31 项为前述换行差异，另 1 项 `frontend/README.md` 不在该发布包中，本次未据此恢复其原始字节。

这条“旧包 → 当时导入清单 → 当时真实 Git 提交”的核对，能够支持来源连续性。旧包和聊天记录的本地哈希用于核对文件与定位记录，不构成第三方可信时间戳或独立著作权认证。

## 如何查看 Git 修改

在本比赛仓库中可以直接执行以下只读命令，无需切换或重置工作目录：

```powershell
# 比赛真实主线
git log main --date=iso-strict --oneline

# 早期发布源码的现在补录记录
git log codex/yuzhou-historical-snapshots --reverse --format="%h %aI %s"

# 查看某条补录的说明和源码变化；把下面占位符换成索引里的 SHA
git show <补录提交SHA>:snapshot.json
git diff <前一个补录SHA> <后一个补录SHA> -- source/
```

第一条补录是留存 0.2.0 部署源码的根快照，不是“空目录直接开发完 0.2.0”的历史证明。现存包之间也可能缺少中间编辑、测试文件、构建工具或未打包的源码。初始对话及代码补丁单独用于说明起点，不伪装成缺失的完整首版。
