## 发现与限制

1. 一次界面发送可能引发最多5次底层模型请求，包括工作台查询及格式修复。每次请求超时180秒，单任务总耗时可能更长；页面消息数量不等于实际调用次数。
2. 当前成功结果只保留模型正文，未保存供应商返回的model与usage，不能从现有任务记录精确核对token消耗或费用。
3. HTTP 402与429统一呈现“请求频率或额度受到限制”，目前不能明确区分余额不足与限流；两者均不会触发格式自动重试。
4. 后端允许旧deepseek-chat/reasoner配置，但前端下拉只列Flash和V4 Pro；旧配置回填可能空选。本轮明确选择V4 Pro，不受此旧配置兼容问题影响。
5. 合成空工作台的一句请求也包含固定行动／查询能力说明，构造后约20,810字符、35,613 UTF-8字节；这不是token计数。不能以“短句”推断应用实际请求很短。
