# DEV-008：侧栏宽度连续调节

日期：2026-10-09。根据用户后续反馈整理；原始摘录见`raw/DEV-008-user.txt`。

用户要求侧栏在最大限制以内自由调整，不应固定为若干宽度区间。DEV-007在松开时将低于180像素的宽度吸附到80像素，导致预览和最终宽度不一致。本轮移除中间区间吸附，让80像素到当前最大宽度之间的实际拖动值均可保存、刷新恢复。180像素仅作为文字显隐的布局阈值，不再限制宽度。

仍保留最小图标栏、最大宽度保护、显式收起与恢复、取消回滚和移动抽屉。不修改原项目、旧app或历史报告。仅在比赛复制件中直接修正，使用合成数据验证。

## 实现与真实迭代

- 宽度大于80即可保存为自定义宽度；小于180只隐藏文字，不再改变实际宽度。读取本机偏好时接纳81、140、179及小数值。键盘左右以20像素连续增减，不再跳过中间区间。
- 首轮新增检查15项中14通过、1失败：179→180的1像素拖动被原2像素门槛拦截。审查代理起初将它判断为夹具问题并调整测试操作；主代理依据“自由调节”要求更正判断，移除产品门槛，并恢复直接微调测试。首轮原始工具输出转存于`../engineering/DEV-008-first-test-failure.txt`，没有将修正后的输入伪装成首轮输入。
- 现在只要指针实际发生位移，就更新宽度；没有移动仍不写入。取消、第二指保护、最大限制和显式收起行为保持有效。宽度本身仍是本机偏好，收起/展开仍沿用工作区`ui.sidebarPinned`。

## 验证

- 16项侧栏检查与5项既有导航检查共21项通过、0失败、0跳过，报告为`../engineering/DEV-008-sidebar-targeted.tap`。覆盖中间宽度、1像素与0.25像素调整、重新挂载恢复、取消、失败与导航。本轮没有重跑全量，DEV-007的421项全量为历史结果，不叠加统计。
- 合成4398浏览器实际拖动至140并刷新，侧栏和正文左边均保持140；179、81松开后也保持。Home后右方向键得到100，再拖动1像素得到101；最后恢复140，未产生横向布局重叠。小数值为事件测试结果，不声称浏览器鼠标硬件已实测0.25像素。
- 浏览器错误日志为空，未读取正式私人内容、未调用真实模型。截图另存`../engineering/DEV-008-continuous-sidebar.png`，不覆盖旧截图。
