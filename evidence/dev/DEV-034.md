# DEV-034 · 同步缓存与存储容量修复

日期：2026-10-17。用户授权检查并修复同步冲突及本地存储已满，保留现有数据，仅改比赛副本，分阶段提交 Git。

## 排查与计划

- 真实界面曾出现同步冲突；新标签启动在 localStorage 写入工作区时抛出 QuotaExceededError，导致空白页。清理数字记录后，正常登录的独立浏览器页面已保留 17 条正常灵感。
- 旧实现为每个标签保留完整工作区、待同步快照，冲突保留又按时间追加整份副本；没有容量迁移和启动失败界面。
- 将当前账号的工作区缓存、待同步内容、恢复副本与草稿迁至本比赛专用 IndexedDB。只有事务完成、读回核对且旧值未被其他标签修改后，才移除对应旧缓存；不删除业务或恢复内容，不读取其他项目、认证凭据或正式数据库。
- 本地持久化失败时保留内存改动、阻止未经持久化的网络提交，提示导出及重试。相同业务内容的重复提交不再误报冲突；实际分歧继续保留双方内容和显式加载流程。
- 用合成账号验证容量、迁移失败、恢复副本、多窗口/并发和同步竞态；真实账号只经正常 UI 核对，不用私人记录制造故障，不调用模型。

本文件后续追加实际结果与限制，旧 DEV、源码交付包、原项目和旧 app 均保留。

## 实际改动

- `workspace-storage.js` 新增账号隔离的 IndexedDB 快照仓库，沿用本比赛缓存标识。旧工作区、待同步内容、草稿及冲突恢复副本逐项转存，事务完成后读回比对；只有旧值仍相同才移除其 localStorage 占位。已有 IDB 与后来旧缓存不同时，两份内容均保留，不按时间猜测覆盖。
- 工作区保存、AI 续聊草稿和界面草稿改用该仓库。待写内容在内存保留，关闭前有保护；网络提交及 AI 审核执行前的同步等待本地持久化。写入失败显示“本机保存待重试”，提供重试/导出，不把读到的业务数据变成空白页。
- 新窗口只在确有待同步内容时承接上一文档快照；干净窗口直接读取服务端。相同待同步 ID 不再按通知时间反复建立恢复副本。
- 比较完整业务内容，仅忽略根级 `updatedAt` 及对象键顺序。已被服务端接收但丢失回执的请求、相同内容的旧待同步缓存可认定已同步；业务差异、数组顺序及嵌套时间差异仍触发保护。未引入不同内容的自动覆盖或自动合并。
- 接收最新内容及审核执行后的持久化等待期间，如果又有编辑，阻止旧结果覆盖新编辑。恢复副本继续通过正常设置页导出。账号名存在相同前缀时，通过 UUID/记录类型边界区分，不读取或迁移另一个账号的缓存。

## 数据备份与边界

- 正式备份仅在正常 UI 导出后核对，不直接读取正式数据库、凭据、Cookie 或本地私有存储值。比赛目录内安全副本为 `yuzhou/.cu-runtime/dev034-safety/pre-update-2026-10-17.json` 和 `post-update-2026-10-17.json`；比对摘要及正式截图同目录。目录已忽略，私有备份、截图和下载原件均不提交 Git，不覆盖旧文件。下载原件保留在用户 Downloads。

- 最初一项新增单测失败源于测试替身把 `setItem` 定义为只读，修正测试替身后通过；没有忽略失败项。另补查发现启动持久化失败和账号前缀边界，并纳入最终版本与全量报告。
