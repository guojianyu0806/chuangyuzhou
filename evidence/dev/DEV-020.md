# DEV-020：自由画布卡片内容随尺寸适配

日期：2026-10-13。原始请求另存 `raw/DEV-020-user.txt`。

## 需求与方案

用户观察到首页自由画布中放大生活回顾卡片后，内部柱图与文字仍保持原尺寸，希望图形随卡片大小自适应。当前插画采用固定像素，正文上下锚点仅扩大空白。

本轮直接调整比赛 `yuzhou/` 复制件：首页自由画布根据卡片宽高共同调整插画、标题、统计和留白。装饰图形等比缩放，保留阴影与层次；紧凑尺寸避免图文遮挡。AI表单保持真实可操作尺寸，不整体拉伸。列表、网格和堆叠保持既有显示，不更改记录或已保存的方块几何。

计划验证生活回顾、课程、灵感、英语、自建空间及自定义方块的大/小/扁/窄尺寸，操作入口、设置尺寸保存与刷新、其他排列模式及AI输入。合成实例中验证，不修改正式账号布局或读取凭据、私人数据库，不调用模型。代码与证据只在比赛目录内，旧app与原项目保持原样。

## 实际实现

`canvas.js`为首页标记`cv-home`，`canvas-responsive.css`仅在其自由画布的卡片上启用命名尺寸容器。字体、图形的比例同时受宽度和高度约束，具有上下限；柱图、箭头、三本书、贴纸与空间图标使用同一长度单位，避免横向或纵向拉伸。保留原颜色、旋转、轮廓、阴影和真实业务数字。

矮卡片缩小头部图标、收起辅助描述，英语装饰改为右上角缩略图，给按钮保留空间；长便笺在较大卡片允许更多内容。AI标题及标志适配，但输入宿主没有transform或zoom，最小卡片通过原滚动区访问表单。列表、两列、三列、堆叠不启用这一命名容器，内部课程/笔记集合与独立阅读器不受影响。

没有迁移、重排或改写正式账号的卡片几何或业务数据；重新加载首页即可使用新样式。

## 失败与修正

- 初版1100×220生活回顾统计底部超过正文约6.6px；宽卡头部图标增长消耗了高度。短卡改为固定紧凑头部，复核溢出为空。
- 既有短英语卡的`display:none`与课程插画的额外`.75`缩放优先级更高，使初版小图隐藏或重复缩放。增加首页作用域后明确覆盖，并修复英语箭头固定40px的级联问题。
- 320×280英语卡的按钮行仍超过正文约30.5px；进一步按容器高度300px切换右上角小型装饰，保持可见并释放正文空间。220×220至默认344高、极宽/极窄等6组复核通过。
- 浏览器两次填写数字时返回输入目标不匹配，停止该批次，重新观察弹窗后再填写；没有把工具粘贴问题记成已确认的应用故障。后续每次先等待弹窗状态稳定再输入。

早期几何与最终观察分别保存在`../engineering/DEV-020-browser-metrics.json`，不将修正前结果写成通过。
