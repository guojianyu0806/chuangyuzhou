# DEV-003：补齐独立模型连接、资料解析和重启入口

日期：2026-10-09。根据原始需求整理：电脑重启后继续完善完整宇宙比赛副本，补齐未完成能力。当前原始指令摘录另存，本文是需求与实施记录，不替代原始开发对话。

已核查问题：完整业务源码已经存在，但AI任务被未安装的Hermes阻塞，普通文本解析也被同一Python依赖挡住；文档没有正文提取入口，课程不能上传DOCX；密钥与引擎状态不一致；重启后容易打开旧比赛实例。

本轮方案：保留原有行动校验、查询、人工确认和版本保护，新增Node官方DeepSeek接口适配；原生读取文本资料，并使用已存在的只读工具Python运行复制件中的文档解析脚本，所有数据与临时文件仍在本比赛目录。补齐课程/工作区正文预览和明确的可用状态，改进双击启动入口。没有安装外部依赖、读取原Key或调用真实模型。

## 实际改动与人类约束

- 保留完整宇宙业务入口、原有人工确认、行动校验、版本冲突和撤销机制；所有修改只发生在本比赛 `yuzhou/` 副本。旧 `app/` 未修改，两个来源工程未写入。
- 默认模型传输改用 Node 内置 fetch 访问 DeepSeek 官方接口，不再被未配置的 Hermes 阻塞。Hermes 实现仍保留为可选底层能力，当前启动器使用直连模式。已保存 Key、引擎存在、真实模型可达是不同状态；没有执行收费调用。
- TXT、Markdown、CSV 原生提取；DOCX、PPTX 和有文字层的 PDF 使用明确配置的现有 Python 工具。已核验此电脑的工具包含 pypdf，未安装依赖；非秘密解析配置、进程 HOME、临时目录及上传原件均在本比赛运行目录。复制到另一台电脑仍需配置可用 Python。
- 新增认证后的资料正文接口，限制同时两项提取，错误提示不返回原始诊断或路径；课程和工作区增加正文预览，课程补齐 DOCX/CSV 上传。
- 手动启动器识别本副本后打开 4397；重复启动复用同一实例，其他程序占用端口时不给它发管理命令、不停止该程序。本次正式实例已恢复，显示首次建号界面；没有代填账号、密码或初始化口令。

以上方案由 AI 根据用户继续完善的目标提出并实施，不能写成用户逐项指定的技术设计。官方接口依据为 [DeepSeek 对话接口文档](https://api-docs.deepseek.com/api/create-chat-completion/)，于本轮核对。

## 真实失败与修复

1. 首次全量检查 329 项：327 通过、1 失败、1 可选跳过。Windows 备份发布发生 EPERM。针对检查单独执行时未复现；据实际失败和代码审查，显式关闭哈希读取句柄，并仅对 Windows EPERM/EBUSY 做有限重试。每次重试仍校验源、目标边界及目标不存在，禁止覆盖已发布备份。新增故障注入验证短暂占用、持续占用、已有目标及其他错误，6 项备份检查通过。原失败报告保留。
2. 浏览器合成验收发现：AI 确认在后端成功，前端却将自身改动显示为“其他设备有更新”，审核卡仍为待执行。改为确认前先同步、期间暂停旧快照上传，完成后回读；无新编辑立即采用结果，有新编辑则保留并显式提示加载，不静默覆盖。5 项新增竞态回归通过。
3. 同一合成浏览器刷新代码后重新生成方案、切到待办再返回确认：确认前 1 件事项，确认后立即显示执行回执，再查看为 2 件事项。首次发现问题时的已执行事项保留，因此第二次基线为 1，不将两个阶段混写成一次成功。
