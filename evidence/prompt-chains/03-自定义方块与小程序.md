# 开发链 03：从可配置方块到可运行、可修订的小程序

覆盖时间：2026-10-09、2026-10-15。对应 DEV-009、DEV-028。本文是依据实际开发记录形成的专业说明；[原始公开对话](raw/chain-03.md)与[早期实现记录](../dev/DEV-009.md)、[真实模型验收记录](../dev/DEV-028.md)分别保留。

## 从用户意图确定能力边界

用户认为内置方块覆盖不足，希望补充常用场景，并让模型自行创建方块。AI 提出“组合内容与字段”和“编写新交互小程序”两条路径，用户明确要求两种都具备。这一选择直接决定了配置型与代码型并存的设计，而非只增加固定模板。

专业需求概括为：**支持用户以自然语言生成可持续编辑的内容组件，以及具有独立交互逻辑的小程序；生成结果先审核，确认后保存，小程序另行手动运行。修改代码应保留已有使用数据，异常输入、停止重启和撤销不能破坏后续内容。** 后半部分是实现与验收中逐步明确的工程约束，不冒充用户逐字提出的原始需求。

## 为什么同时修改提示、运行器和数据处理

生成代码首先要遵守可执行接口。首次 `app.getData` 报错并非模型请求失败，而是代码将 `app` 重新绑定到 `this`，造成运行器 API 不可用。[f35b87f 原始 diff](diffs/f35b87f.patch)保留新增接口说明及合法输入保存示例：区分空字符串、检查有限数值及业务范围、错误只展示不保存、等待保存成功后再反馈。示例是约束和参考，不保证模型以后不会生成错误代码。

宿主也必须能从失败中恢复。[282a536 diff](diffs/282a536.patch)修复停止、异常和早期校验后的运行按钮状态；[3903106 diff](diffs/3903106.patch)修复根自定义方块私有 JSON 的 `fileId` 等字段被误当作宿主附件。历史记录仍明确通用递归扫描在其他上下文中的潜在边界，不能写成所有同名字段问题都已解决。

撤销保护需要精确到实际被修改的对象。同批创建 A、B 后，仅 B 被使用时，旧实现可能连未改的 A 也保留。[86c03fe diff](diffs/86c03fe.patch)与[修复前报告](../engineering/DEV-028-block-partial-undo-red-2026-10-15T13-53-37-656Z.tap)、[修复后报告](../engineering/DEV-028-block-partial-undo-green-2026-10-15T13-54-27-667Z.tap)对应这一问题：清理可撤销对象，同时保持 B 的后续数据与布局保护。

## 能力与证据边界

代码在隔离运行器中使用受控组件及所属方块的数据 API，没有任意外部软件操作、联网、依赖安装或主页面 DOM 控制能力。创建、更新、手动启动分别有清晰步骤，审核确认不会自动运行程序。
