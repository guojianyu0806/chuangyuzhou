## 如何专业呈现开发方法

链 01 最适合展示人工纠偏：先展示用户指出拖入功能回退的原句，再对照 AI 定位、`154e54e` 的实际修正与浏览器结果。链 02 可展示结构化查询契约、确认前保护和状态校验；链 03 可展示真实代码生成失败、接口约束改进及保留使用数据的修订。视频中应讲解这些实际变化，而不是重新表演一段不存在的历史聊天。

链 02、03 的缺陷级反馈主要来自 AI 联调与复核；人提供的是方向、范围和继续验证要求。不能为迎合“人类引导”而改写为人逐条发现所有漏洞。产品内 DeepSeek 的调用结果属于功能验收，与 Codex 辅助开发对话分别呈现；工程通过数、模型调用数、真人使用效果也分别陈述。

## 本地核验

在仓库根目录执行：

```powershell
python evidence/prompt-chains/archive_dialogues.py verify
python evidence/prompt-chains/archive_git.py verify
python evidence/prompt-chains/verify_package.py
```

第一条检查原文摘编哈希及两种格式一致性；可另加原日志路径做作者本机源文件复核。第二条要求完整本地 Git 历史，用真实提交重算差异。第三条检查本包说明链接、原文锚点、历史测试统计、文件在 Git 中的字节一致性及遗留证据未变。所有命令只读，不访问正式账号、模型或私人数据库。
