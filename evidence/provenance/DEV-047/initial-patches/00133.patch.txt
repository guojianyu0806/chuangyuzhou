+# 个人学习工作台：调研与产品初稿 V0.1
+
+本稿整理于2026年9月19日。当前交付是公开资料调研和可继续开发的产品定义，尚未生成实际工作台、连接API、读取聊天记录或部署云服务。

+## 已确认的需求
+
+- 本人使用，两台Windows电脑、vivo X100s手机、vivo Pad3 Pro平板。
+- 采用私人云端方案，电脑关机后手机和平板仍可使用。
+- 软件工程专业，当前备考六级；每日英语时长之后再定，不预设分数或考试日期。
+- 可提供DeepSeek、豆包等国产模型API，用于整理碎片、课程资料和待办。
+- 按课程投喂PPT、课堂笔记，生成重点和学习笔记；不同课程有独立上下文与助教规则。
+- 包含英语规划、备忘录，并探索微信QQ只读消息汇总；不能自动回复或代发。
+- 源码可持续修改，发布后其他设备能收到站内更新提示并更新。
+- 视觉为霓虹色彩、亮色为主。

+## 每天怎么用
+
+课后在电脑上进入某门课程，拖入课件和笔记。工作台保留原件，显示真实的处理进度，整理完成后给出章节重点、疑难点、代码解释和复习问题。晚上在平板打开同一课程，继续阅读原文与整理笔记，点引用可以回到资料来源。
+
+收到“周五前交作业”这样的消息时，先把文字或截图放进收集箱。AI提取作业名称、截止时间和来源，明确的信息生成任务草稿；日期缺少参照或语义不明确时标为待确认。手机首页显示已保存的待办，用户可以完成或重新安排。
+
+六级区依据实际设置和练习结果安排后续任务。尚未确定每天学多久时，保留“开始一次练习”和“稍后设置计划”，不会强行分配每天60分钟或编造考试倒计时。
+
+首页示例为“今天有3件待办·2份资料已整理待查看·六级有1项练习待完成”。这些数仅用于说明界面，实际使用必须由真实数据产生。首次打开显示上传引导，不能把演示数字混入个人数据。
+
+## 课程助教应该怎样工作
+
+“提前调教”先做成课程规则、笔记模板、学习者信息和资料检索，不预设需要训练或微调模型。工作台负责保存这些信息，每次请求选取相关内容传给模型。DeepSeek官方说明多轮对话接口是无状态的，需要应用自行传入历史上下文。[DeepSeek多轮对话](https://api-docs.deepseek.com/guides/multi_round_chat/)
+
+每门课程保留一份可修改的助教说明：课程名、教材或教学大纲、章节结构、老师明确强调的内容、用户已确认的更正、输出格式与解释深度。模型知识用于解释时应注明“补充说明”，与课件原文结论区分。
+
+软件工程方向的默认笔记模板建议包含：
+
+1. 本章解决的问题和核心概念。
+2. 概念关系、适用条件与容易混淆的点。
+3. 算法、代码、公式或图示的逐步解释，保留原始代码与单位。
+4. 例题、测试输入或边界情况；只有真实执行过的代码才能称为“已运行验证”。
+5. 老师明确标注的重点，以及单独标识的AI建议复习点。
+6. 用户笔记中的疑问、原资料冲突或无法确认之处。
+7. 3—5个复习问题及其原文页码。
+
+处理路径：上传原件→提取可选文字→必要时将页面转图并识别→按课程和章节保存→检索原文片段→生成笔记→校验引用与结构→保存新版本。
+
+PPT中的图、代码截图、扫描页和手写内容不能只靠纯文本抽取。解析质量不足的页要显示待核对，允许对照原页修正。引用必须对应真实文件和位置，避免模型编造页码。
+
+截至本次调研，DeepSeek已提供Files API，但官方列出的文件格式是JPEG、PNG、GIF、WebP图片，不能直接当作完整PPT/PDF解析与知识库服务。[上传文件文档](https://api-docs.deepseek.com/zh-cn/api/create-file/)
+
+豆包可以通过火山方舟接入；工具调用需要工作台实际执行功能。文档解析也可以使用独立的火山知识库服务，其文档列出PPT整页解析和图片OCR等能力，是否采用及费用需要实现阶段再选定。[方舟工具调用](https://www.volcengine.com/docs/82379/1958524?lang=zh)、[知识库文档解析](https://www.volcengine.com/docs/84313/1254457?lang=zh)
+
+## 自动整理的具体范围
+
+自动执行低影响且可撤销的操作：识别资料类型、生成摘要、建议标签、按已保存的规则归类、建立关联、生成待办草稿。保留原件、来源和处理记录。低把握的归类进入待整理区；相同文件或消息的重复输入应去重。
+
+用户修改过的笔记不被后台静默覆盖；重新整理生成新修订，允许比较和恢复。模型只返回受限制的操作建议，后端负责校验后保存。资料里的文字不能改变系统规则，消息中出现指令也不应触发代发或其它外部动作。
+
+API密钥存于服务端，不出现在网页源码或浏览器存储。失败任务显示原因并允许重试；记录调用量，避免重复点击造成重复处理与计费。输入材料由已选模型服务处理，设置中说明实际使用的服务和数据范围。
+
+## 六级区的基础功能
+
+首次设置仅需逐步补充：目标考试、可用时间、已有成绩或自测结果、个人薄弱项。已确定exam_level=CET-6，其他值允许为空。
+
+首版支持周计划、今日练习、错题与复习安排，覆盖词汇、阅读、听力、写作、翻译。根据用户实际完成和错因调整，错过一天不要求补齐整个旧计划。听力材料需要用户提供或来自有使用权限的资源；AI生成练习必须标明来源属性，不能冒充历年真题或官方评分。
+
+写作和翻译反馈应显示原句、修改建议与原因。对主观题提供参考评价；不把模型分数展示为官方成绩预测。四六级考试日期只有在用户输入或实施时核实官方信息后才显示倒计时。

+## 四台设备如何共用与更新
+
+推荐形态是响应式网页，配合可用时的PWA桌面入口。四台设备使用同一账户和同一后端数据；PWA本身不是数据库同步方案。Windows上的Edge支持将PWA作为应用安装。[Microsoft说明](https://learn.microsoft.com/en-us/microsoft-edge/progressive-web-apps-chromium/ux)
+
+vivo手机和平板以浏览器访问为基础保障。桌面入口、独立窗口与系统通知取决于实际浏览器、系统和网络；无GMS等环境下不应统一承诺完整WebAPK安装体验。[MDN安装支持](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable#browser_support)
+
+三件事分别实现：
+
+- 数据同步：上传笔记、修改任务后写入云端，另一设备联网时获取变更。每次更新带记录版本；冲突保留双方修订，避免覆盖另一端未同步的文字。界面区分本机已保存、待同步、已同步和失败。
+- 功能更新：本地源码修改→验证→发布到同一网址→客户端检查版本→显示新版本提示→保存草稿后刷新。需要处理旧页面缓存与后端兼容，并保留部署回滚能力。[PWA更新机制](https://web.dev/learn/pwa/update)
+- 系统通知：关闭网页后的推送依赖权限、浏览器、网络与平台推送服务。首版承诺站内通知、打开及恢复前台时检查更新；后台必达通知要等两台vivo实机验证后再决定实现方式。[MDN后台与推送](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Offline_and_background_operation)
+
+因此，“电脑改完，手机和平板更新”需要发布步骤；仅修改电脑上的源码文件不会让远端页面自动改变。拟选国内可访问的云部署，具体服务商、预算和域名另行确定，本次不创建云资源。
+
+云端保存应用数据、资料和处理任务；电脑关机不会影响已部署服务。个人身份验证、资料私有访问、备份和Markdown等通用格式导出属于首版基础能力。云服务与模型调用有持续成本，本次没有选择付费套餐或估算未经核实的价格。
+
+## 亮色霓虹的界面方向
+
+浅紫白背景与白色内容纸面占主要面积；青、紫、粉和少量荧光黄绿用于导航、按钮、分区标题和状态。长篇笔记采用深色文字，引用标记有清楚的下划线或按钮形态。选中课程或完成一次整理时可以出现短暂柔光，不做持续闪烁背景。
+
+电脑：首页左侧导航，中央优先任务与课程内容；课程页可打开右侧助教。平板：课程目录可收起，正文和原页双栏对照。手机：今日、课程、六级、收集、更多五个底部入口；收集按钮易于单手触达，阅读页把对话与原文切换成独立视图。

+## 建设顺序与验收
+
+1. 先完成一个闭环：上传一份课程资料→生成带真实来源的笔记→保存一条待办→另一设备能读取。用用户真实的少量课件验证解析，特别检查代码截图、图表和公式。
+2. 首个完整可用版本纳入六级基础规划、备忘录、碎片自动分类、站内更新提示与草稿保护。可用时间未设置时六级区仍能进入练习。
+3. 再增加周回顾、指定QQ群机器人，以及经过实测的Android通知摘要或系统推送。消息连接器不阻塞学习功能上线。
+
+验收以真实操作为准：Windows两端和vivo两端实际打开；跨设备保存与读取；编辑冲突不会丢稿；应用更新保留草稿；引用能回到原页；模型失败能重试；未经连接的消息源不会显示已接入；未配置英语计划不显示假任务或假倒计时。
+
+## 已经想过但暂未纳入
+
+第一阶段不设计商业化、多用户团队权限、复杂知识图谱、全量私人聊天抓取或自动代发。Android原生壳仅在实际通知和系统整合需求出现时再评估。这里是建议的阶段安排，只有“消息只读”是用户明确的功能限制，其余均可在后续讨论中调整。

+## 给实现方
+
+- 本文件是产品初稿，不代表功能已经存在，也不代表已授权安装、云部署或账号连接。
+- surface=both表示同一网页适配电脑、手机、平板；先保障浏览器可用，再逐设备核验桌面入口和通知。
+- 按home的顺序组织首页；hook为行动摘要，其中数字必须由hook.fields列出的数据计算。示例数字不得混入个人账户。
+- channels是导航模块，does说明可完成的动作。weight=primary只有“今日”，它是默认首页；学习回顾放到后续增强版本。
+- pages里的L1是模块首页，L2是单项详情，L3只用于课程中具体资料或笔记。按照shows选择清单、时间流、课程卡片或原文对照，不把所有页面都做成数据表。
+- pipeline表示从收集到整理再到使用的状态流转；registry表示资料可检索、可打开详情，不要求首屏一定画成列式看板。
+- entities给出最小概念模型，不是最终数据库迁移脚本。user是用户输入，system是程序产生，integration是外部服务返回，derived是根据已有字段计算；带or的字段须按实际操作记录来源。
+- 模型输出先校验再保存，引用必须指向可验证的资料片段；不能把任意模型返回内容当作数据库指令。
+- 按cold_start设计首次使用和回访。depends_on尚未接入的来源不得显示虚假的同步状态或统计。
+- 明确显示AI处理状态、同步状态、最近同步时间。服务端保存API密钥，用户能导出原件、笔记及任务数据。
+- 按visual实现浅色霓虹；正文必须易读，手机不横向滚动，输入框不被键盘遮住，所有状态有非颜色提示。
+- 后续修改需求文档时遵守用户版本管理规则：要求新版本则另存；要求直接修改则只改指定文件；意图不清时先询问。
